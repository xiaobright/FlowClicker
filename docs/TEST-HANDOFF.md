## 本地假 AI 服务

运行于 Windows 回环地址，无外部请求、无需密钥，不记录请求正文或图片。

```powershell
# 在项目根目录运行；前台进程，用完成后的 Ctrl+C 结束，不杀其他 Python 进程。
uv run --no-project 'E:\Desktop\mytests\android-test\tools\mock_ai.py' --scenario reply
# 在另一终端：
& 'D:\androidsdk\platform-tools\adb.exe' -s '<serial>' reverse tcp:8765 tcp:8765
```

App 中保存：baseUrl=`http://127.0.0.1:8765/v1`，model=`fake`，key 留空，启用 AI。debug APK 仅对回环/模拟器宿主地址放开 HTTP；release 不含该例外。

`http://127.0.0.1:8765/stats` 返回请求数量、时间、消息数量、状态码。每个场景重新启动假服务以清零计数。不要为了等结果不停刷新；普通步骤等待 5–15 秒，后台长任务至少间隔 1 分钟检查，遇到结束事件可提前收集结果。

场景：

- `reply`：立即回复，不执行工具。
- `auth`：始终 401。
- `retry`：第一次要求新建一个禁用的 `回归·只创建一次` 任务，第二次返回 503，第三次回复。
- `late-action --delay 15`：首次请求延迟后才返回创建任务指令，后续请求仅回复，用于停止/重新启动的迟到结果测试。
- `max-rounds`：每次都要求 `log_note`，验证上限。
- `invalid-json`：每次返回不符合协议的文本。
- `--script <文件>`：替代上述场景，文件为 JSON 数组，每项可设 `assistant`（reply/tool/args 对象）、`status`、`delay`；超出数组后只回复。可以用来确定性设置任务、规则、试跑、读取结果、转正，不需要真实模型。

脚本示例（创建单个测试任务，随后结束；ID 由 App 分配）：

```json
[
  {"assistant":{"tool":"upsert_task","args":{"task":{"id":0,"name":"回归·文字验证","trigger":{"keywords":["仅用于手动试跑"]},"steps":[{"type":"wait_text","text":"权限设置","present":true,"timeoutMs":5000}],"enabled":true,"mode":"debug"}}}},
  {"assistant":{"reply":"创建完毕，请回到主界面后试跑。"}}
]
```

设置 `run_task_now` 后当前会话需要先结束，任务才会拿到屏幕控制权执行；这是有意的互斥语义，不是死锁。从 `get_task` 读取完整 task（包含 revision）后才能编辑；版本冲突必须重新读，禁止去掉校验。

## P0：停止后绝不自动复活（必须全部通过）

### S01 停止时模型还没返回

1. 启动 `late-action --delay 15`，记任务列表和 `/stats`。
2. 手动唤醒，确认服务收到了请求，在返回前点击 App“停止全部自动操作”。
3. 等服务的迟到响应结束，再观察至少 1 分钟。
4. 预期：不会新建 `回归·只创建一次`，不会启动引擎、点击或发起新的模型请求；状态保持停止/空闲。

### S02 停止后立即手动开新一轮

重复 S01，但停止后立即再次手动唤醒。新一轮正常收到“模拟端点已收到事件”；旧一轮的迟到创建指令仍不能执行。对比停止前后的任务数量与请求时间线。**仅证明新会话可用不够，必须证明旧工具未执行。**

### S03 后台任务完成与看门狗到期

让一个任务包含较长等待，并配置短 idle/stall；再排队一个试运行/复盘事件。停止全部操作后等超过原任务完成时间和看门狗超时。预期：任务取消，不续跑下一步；不消费旧队列；不新增 AI 请求。再次手动启动后也不重放旧试运行。

### S04 停用 AI 与全部停止的区别

- 只取消勾选 AI 并保存：当前 AI 会话取消，旧事件丢弃；本地引擎可以继续，不再调用 AI。
- 点击全部停止：AI、本地引擎、临时测试和录制均停止；正在转发的手势不能导致录制器再次唤醒 AI。
- 从采集通知上的“停止全部操作”重复验证。
- 系统已经接收的单个手势不能撤回，允许当前短手势收尾（最长 5 秒，加回调等待）；但绝不能再派发下一步。

## P1：数据与执行正确性

### D01 临时全链路测试不改任务库

至少准备两个已有任务；备份 tasks.json 后点击首页全链路测试。预期只验证当前页文字并打开无障碍设置；任务列表、ID、开关和文件内容不变。重启应用后再确认。引擎/AI/录制忙时应拒绝测试，而不是覆盖或抢操作。

### D02 UI 旧快照与版本冲突

- 停留在任务列表期间，让 AI 修改任务 A、新增任务 C；手动切换 B 的开关。A/C 的修改必须保留。
- 打开 A 编辑器，再让 AI 修改 A 的定义；旧编辑器保存应提示冲突，不能覆盖。
- AI 只切换 A 的 enabled 或 mode 时，编辑器保存其他字段须保留最新的开关和 mode。
- 删除 A 后旧编辑器保存不能将它复活。

### D03 debug 状态保留

用 AI 创建 debug 任务，在 UI 只修改名称并保存。仍为 debug，不应静默转 normal。已有 wait_text 可在编辑器修改，不显示“不支持编辑”，没有重复分支行为。

### E01 失败不得报成功

撤销无障碍、取消手势、采集停止/撤销授权分别测试。预期阻止启动或产生失败/取消结果，`completed=false`，不能累计为成功轮次或转正；不能持续刷失败点击。

### E02 结果验证与转正门槛

1. 末步 wait_text 等待实际存在的文字，试跑后 `completed=true, verified=true`，保存 runId/revision。
2. 改为不存在的文字，超时后 `completed=false, verified=false`，原因明确，任务暂停。
3. 没有末步 wait_text 的任务即使手势都完成也只能 `verified=false`，AI 转 normal 被拒绝。
4. 验证成功后修改定义，再直接转 normal 必须拒绝，不能沿用旧 revision 的证据。
5. debug 自动跑满轮数后暂停继续重复；复盘事件携带正确 taskId，能读取结果和会话笔记。

### E03 OCR 锚点与输入校验

锚点不存在或多个匹配时默认停止；只有明确开启 anchorFallback 才能使用旧坐标。负数/NaN/越界坐标、倒置区域、空文字等待、过大手势/抖动均应拒绝或明确失败，不能崩溃或假成功。

### E04 三方互斥

本地任务 A1→等待→A2 期间唤醒 AI 直接操作 B；必须得到完整 A1/A2 后才执行 B，或用户先取消 A；不能 A1/B/A2。录制期间本地任务和 AI 同样不能插入操作；结束/取消录制后控制权正常释放。

### E05 录制时序

录制 A→等约 5 秒→B→等约 1 秒→C。检查存储：5 秒属于 A.delayAfterMs，1 秒属于 B.delayAfterMs，不应整体后移。回放节奏与录制一致（允许实际手势转发开销）。转发失败的手势不应保留为成功记录。

## P2：AI 调度、协议与设备生命周期

### A01 请求重试不重复副作用

使用 `retry`，一次手动唤醒。预期假服务收到 3 个请求，任务只增加 1 个，不是两个；第二、第三请求应处于同一会话进度。随后 `auth` 只收到 1 个请求；不做 5s/15s 无意义重试。

### A02 有界队列与工具轮数

延迟模型回复时连续制造超过 5 个不同事件，并重复同任务的同类事件。等待队列不超过 5，同类事件合并；超过 2 分钟的事件不执行。`max-rounds` 配置 N=2 时最多产生两条 log_note；多余工具请求不能执行。非法 JSON 重试有界并结束，不进入循环风暴。

### A03 stall / scoped idle

- A 不断自我触发，B 从未接续：stall 仍必须到期。
- A 完成后另一个任务 B 触发：满足“其他任务接续”，旧 stall 取消。
- 针对任务 A 的 idle，不应被无关 B 的持续活动掩盖。
- AI/录制接管屏幕期间不产生错误 idle 风暴。

### A04 截图、笔记与协议

检查 get_task 返回标准 JSON 的 task/note；截图文件列表为有效 JSON；get_screenshot/describe_screen 返回原始和传输图像尺寸。自动 debug/test_run_finished/stall 都携带 taskId，任务笔记可注入；会话文本有上限，不保存 base64 原图。截图 step-1 表示操作后帧，必须结合执行结果，不能单凭截图声称成功。

### L01 旋转与权限

运行中旋转、撤销采集或关闭无障碍：自动操作应停止，而不是沿用旧坐标。旋转后需重新授权采集并校准坐标。重复点击开启采集不应创建多个采集线程。不同分辨率验证不能依赖固定 1080×2340。

### L02 有界长跑

仅在测试画面运行 15–30 分钟，记录开始/结束及至少一个中间点的内存、CPU、任务数量、AI 请求数、截图数。每任务截图保留上限 12。观察是否出现持续增长、卡死、状态显示运行但实际协程已退出。不要使用真实账户挂机验证。

## 证据与结案要求

每项填：PASS / FAIL / BLOCKED / NOT_RUN，设备信息、APK 哈希、步骤、预期、实际、截图/日志路径。不能用“编译成功”“HTTP 200”代替功能通过，不能将任务回调完成等同业务成功。

失败优先提交 S01–S04、D01–D03、E01–E04 的最小复现。日志仅保留必要时间窗口，脱敏密钥和屏幕内容。不自行重置、卸载、清数据、提交或推送。

完成后：停止测试任务、关闭假服务、仅移除自己添加的 adb reverse 映射，恢复之前 AI 配置与用户任务；保留原始测试证据。
